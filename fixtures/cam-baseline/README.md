# M0 CAM fixtures

Generated by `python scripts/generate_cam_baseline.py` using standard-library math and literal geometry, independently of the Rust CAM algorithms. These are synthetic inputs and are not machine-ready programs.

| File | Exact intent / expected observation |
| --- | --- |
| `pocket-island.warp` | Outer rectangle (2,2)-(38,28), island (15,10)-(25,20), 3 mm flat tool, offset pocket to -2 mm in 1 mm levels |
| `open-profile.warp` | Open L (5,5)-(20,5)-(20,15), on-curve profile; 25 mm horizontal travel at each of two cut depths |
| `drill-pattern.warp` | Four radius-2 circles at (8,8), (32,8), (8,22), (32,22); peck drill to -2 mm |
| `sculpted-parallel.warp` | Ball tool over 600 triangles sampling z=-0.002*((x-20)^2+(y-15)^2), x=0..40, y=0..30, 2 mm vertex spacing |
| `projected-open-curve.warp` | Open L projected onto the same mesh; currently fails closed-containment validation, tracked as M0-K01 |
| `planar-mm.dxf` | Two rectangles, open L and four actual circle entities; explicit millimeter units |
| `sculpted-mm.stl` | Same 600-triangle analytic surface, ASCII STL; unitless format, fixture convention is millimeters |
| `tools.json` | Frozen tools/feeds independent of `ToolLibrary::starter()` and user settings |
| `benchmark.json` | Inputs, measurement protocol and required metrics |

Every project is an intentionally frozen legacy/unversioned `.warp` document. M1 must retain them as migration inputs rather than rewriting them in the new format. Each project contains one operation and stock (0,0,-5)-(40,30,0) mm. Tools are not embedded in legacy projects; the benchmark loads this directory's library explicitly. Do not depend on the user's tool numbers matching the fixture library when opening a fixture in the UI.

Import tests check geometry, count and units independently of entity ordering. STL coordinates incur float32 conversion on import; vertex assertions allow 1e-6 mm. The sampled paraboloid peaks at -0.002 mm because the grid does not include y=15; the continuous analytic surface peaks at 0. This distinction must not be hidden by an overly loose bounds test.

Run `cargo test -p warp-cam --test baseline` for characterization tests and `cargo run -p warp-cam --example cam_baseline --release -- <output.json>` for benchmark measurements. Performance is informational, not a timing-sensitive CI assertion. See `docs/baselines/M0_BASELINE.md` for recorded results and limitations.

For a report with hardware/toolchain metadata and input/source SHA-256 hashes, run `./scripts/run-cam-baseline.ps1`. It writes to `target/cam-baseline` by default; pass `-OutputDirectory` to choose another location. This does not change the committed M0 record unless explicitly pointed at that directory.
